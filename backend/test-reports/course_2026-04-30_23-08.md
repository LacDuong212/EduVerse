- `EDV-186 · Error: instructor not owner + draft course → 400 'unavailable'`
- `EDV-204 · Error: draft course (guest) → 400 'unavailable'`

**Fix**: Changed test to use `INSTRUCTOR_LACDUONG` (who does NOT own `PUBLIC_LIVE_COURSE_ID`) as the actor instead — verifies the `isOwned: false` path correctly.

## Bugs Discovered in Production Code

### EDV-273 — Sort by rating uses total sum, not average (MEDIUM)
**File**: `src/modules/course/course.service.js`, `getMongoSort()`  
**Root cause**: `ratingHighToLow` maps to `{ "rating.total": -1 }` and `ratingLowToHigh` to `{ "rating.total": 1 }`. Sorting by `rating.total` (cumulative sum) is incorrect — a course with 1,000 mediocre reviews will outrank a course with 5 perfect reviews. The correct sort is by average (`rating.total / rating.count`), which requires either an `$addFields` aggregation stage or a precomputed `rating.average` field.  
**Impact**: Courses sorted by rating return results in wrong order for users browsing `GET /api/courses?sort=ratingHighToLow`  
**Test action**: No test asserts ordering; no test change needed  
**Jira**: EDV-273 filed ✅

### EDV-274 — Sort by price ignores `discountPrice`, discounted courses ranked incorrectly (MEDIUM)
**File**: `src/modules/course/course.service.js`, `getMongoSort()`  
**Root cause**: `priceLowToHigh` maps to `{ price: 1 }` and `priceHighToLow` to `{ price: -1 }`. When `enableDiscount: true`, the effective price is `discountPrice`, not `price`. A course with `price=100, discountPrice=5` would appear near the end of a low-to-high sort despite having the lowest effective price.  
**Note**: The in-memory `sortDocs()` function correctly uses `getEffectivePrice()` — the bug only affects DB-sorted queries (non-search path).  
**Impact**: Wrong ordering for users browsing by price when discounts are active  
**Test action**: No test asserts ordering; no test change needed  
**Jira**: EDV-274 filed ✅

## Observations (No Bug — By Design)

1. **`sortDocs()` (in-memory) is correct** — uses `getEffectivePrice()` for price and `getAverageRating()` for rating. The bugs are only in `getMongoSort()` which is used for the non-search DB path.

2. **`LEVEL_ENUM` key vs value mismatch** — `LEVEL_ENUM = { beginer: "beginner" }` (key typo, value correct). Since the model stores and validates the value `"beginner"`, this is cosmetic and has no runtime impact.

3. **`getCoursePublicDetails` populate path `instructor`** — The course schema embeds `instructor.ref` (ObjectId) and denormalized `instructor.name/avatar`. The populate `{ path: "instructor", select: "name pfpImg" }` targets the embedded subdoc's `ref` via virtual population — this works correctly in Mongoose with `localField`/`foreignField`.
