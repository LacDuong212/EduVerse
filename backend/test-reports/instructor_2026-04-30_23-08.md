## Bugs Discovered in Production Code

### EDV-271 — Typo in blocked-account error message (LOW)
**File**: `src/modules/instructor/instructor.service.js`, `handleBecomeInstructor()`  
**Summary**: Error message reads `"Your acccount is blocked."` (double-c) instead of `"Your account is blocked."`  
**Impact**: Minor — UI shows misspelled error message to blocked users calling `POST /api/instructors/`  
**Test action**: No test asserts this exact message (the `already an instructor` path is tested, not the blocked path) — no test change needed  
**Jira**: EDV-271 filed ✅

### EDV-272 — PATCH /instructor/profile response missing `isActive` field (LOW)
**File**: `src/modules/instructor/instructor.service.js`, `updateInstructorProfile()`  
**Root cause**: `instructor.populate()` uses `select: "name email phonenumber pfpImg website socials"` — `isActivated` is not in the select, so `instructor.user.isActivated` is `undefined` when `toInstructorDetails` maps it to `isActive`. The `GET /api/instructor/profile` response (a fresh query) correctly includes `isActive`.  
**Impact**: API inconsistency — PATCH response omits `isActive` while GET includes it  
**Test action**: Added `test.failing("PATCH profile response should include isActive (EDV-272)")` in the Update Profile describe block  
**Jira**: EDV-272 filed ✅

## Observations (No Bug — By Design or Intentional)

1. **`insId` commented out in `toInstructorDetails` mapper** — The public profile response intentionally omits `insId`. Tests do not assert `insId` on public profile, so this is consistent. No bug filed.

2. **`totalOrders: undefined` when `isPrivate === false`** in `getInstructorStats()` — Private stats include `totalOrders`; public stats omit it (JSON serialization drops `undefined`). Tests assert the correct shape for each case. No bug.

3. **`getCurrentInstructor()` returns `insId: instructor?.user?._id || instructor.user`** — Returns the user's `_id` (not the instructor document `_id`). This is consistent with how the frontend identifies the instructor record.

4. **`createNewCourse()` increments `instructor.stats.totalCourses`** — Counter incremented at creation time, not at approval. This is a design choice, not a bug.
