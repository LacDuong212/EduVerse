## 6. Bug Reports

### BUG EDV-259 — `thumbnail` Always Null in Wishlist Responses [Medium]

| Field | Detail |
|-------|--------|
| **Jira** | EDV-259 |
| **Severity** | Medium |
| **File** | `src/modules/wishlist/wishlist.mapper.js` |
| **Root cause** | Mapper reads `course?.thumnail` (misspelled) but Course model field is `thumbnail`. Property access always returns `undefined`, coerced to `null`. |
| **Actual** | `thumnail: null` in all wishlist DTO responses |
| **Expected** | `thumnail` contains the thumbnail URL string from the course |
| **Impact** | All frontend thumbnail images in wishlist are broken |
| **Reproducing test** | Test #4 — `[BUG EDV-259] thumnail field should contain thumbnail URL` |

**Failure:**
```
expect(item.thumnail).not.toBeNull()
Received: null
```

---

### BUG EDV-260 — `lectureCount` Phantom Field Always 0 [Low]

| Field | Detail |
|-------|--------|
| **Jira** | EDV-260 |
| **Severity** | Low |
| **File** | `src/modules/wishlist/wishlist.mapper.js` |
| **Root cause** | Mapper reads `course?.lectureCount` but Course model only has `lecturesCount`. Returns `0` (falsy fallback). A phantom field `lectureCount` is emitted in the DTO. |
| **Actual** | `lectureCount: 0` in all wishlist DTO responses; real value is in `lecturesCount` |
| **Expected** | Either `lecturesCount` is correctly mapped, or `lectureCount` field is removed |
| **Impact** | Lecture count always displays as 0 in wishlist UI |
| **Reproducing test** | Test #5 — `[BUG EDV-260] lectureCount should be removed (always 0, Course has lecturesCount)` |

**Failure:**
```
expect(received).not.toHaveProperty("lectureCount")
Expected path: not "lectureCount"
Received value: 0
```
