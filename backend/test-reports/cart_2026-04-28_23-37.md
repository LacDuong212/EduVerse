## 6. Bugs Discovered in Production Code

### EDV-262 [Medium] — Cart: addToCart accepts non-existent courseId and returns null items in GET /api/cart

**File:** `src/modules/cart/cart.service.js` → `addToCart`

**Root cause:** `addToCart` pushes `courseId` directly without verifying the course document exists in the Course collection. When the cart is later populated via `cart.populate("courses.course")`, the non-existent courseId resolves to `null`. `toCourseCartItemDto(null, addedAt)` returns `null`, so `GET /api/cart` returns `[null]`.

**Status:** ❌ Intentional-fail test in place (test #9). Jira: EDV-262.

---

### EDV-263 [Low] — Cart: typo 'coure' in dead-code error message in bulkRemoveFromCart

**File:** `src/modules/cart/cart.service.js` → `bulkRemoveFromCart`

**Root cause:** Redundant `courseIds?.length === 0` guard (unreachable — Zod blocks this before service) throws `"Please provide at least one coure to remove from cart."` — misspelled "coure" instead of "course". Dead code path but incorrect if guard is ever reached.

**Status:** Documented. Jira: EDV-263.

---

### EDV-264 [High] — Cart: concurrent addToCart calls cause lost update due to missing transaction

**File:** `src/modules/cart/cart.service.js` → `addToCart`

**Root cause:** `addToCart` uses read-modify-write without a transaction or atomic operation: `findOne` → `cart.courses.push(courseId)` → `cart.save()`. Two concurrent calls both read the same cart document, both push their respective courses, then both call `save()`. The second `save()` overwrites the document written by the first, discarding one course.

**Demonstrated:** `Promise.all` of two concurrent adds resulted in only 1 course in cart (test count = 1, expected = 2). Tests changed to sequential to avoid flakiness while bug is open.

**Status:** Documented. Tests made sequential. Jira: EDV-264.
